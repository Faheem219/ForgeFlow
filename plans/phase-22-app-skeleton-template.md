# Phase 22 — Fixed-stack app skeleton template

## Title & ID

- **ID:** `phase-22`
- **Title:** Fixed-stack app skeleton template
- **Epic:** Epic 4 — Build Stage (agentic codegen)
- **Milestone:** M2

## Goal

An opinionated, **always-reused** MERN-TS skeleton under `templates/app-skeleton/` — a complete React+Vite+TS+**Tailwind** frontend and Express+TS+Mongoose backend — that the codegen agent *fills in* rather than regenerates, raising first-pass success and cutting tokens.

## Context

Implements D2 (fixed generated-app stack) and the **user directive**: *a base React + Tailwind template must always be used for every user project so the LLM never rebuilds the frontend scaffold from scratch (token waste).* The agent only writes feature code onto this skeleton (`phase-23`). This is the single biggest first-pass-success and cost lever (risk §12: "cache/skeleton to cut tokens").

## Detailed tasks

1. **Frontend skeleton (`templates/app-skeleton/frontend/`).** Complete, runnable, **never regenerated**:
   - Vite + React 18 + TS (`strict`), **Tailwind pre-configured** (`tailwind.config.ts`, `postcss.config.js`, base styles), React Router, a typed **API client** (`src/lib/api.ts`) reading `VITE_API_BASE_URL`, a base layout + example page, env contract (`.env.example` with `VITE_API_BASE_URL`).
   - Test scaffolds: Vitest + Testing Library config + one example unit test; Playwright config + one example E2E (pointed at the preview base URL) — so generated tests slot in.
   - Clear **fill-in markers**/conventions (e.g., `src/features/<feature>/`, `src/routes.tsx`) telling the agent *where* feature code goes.
2. **Backend skeleton (`templates/app-skeleton/backend/`).** Express + TS, Mongoose connection (reads injected `MONGODB_URI`), **Zod** validation, `/health` route, centralized error middleware, config module, request logging; Jest + supertest config + one example unit test; a `src/features/<feature>/` convention for routes/models/controllers.
3. **Shared conventions.** Root `templates/app-skeleton/README.md` documenting the layout, the fill-in points, naming conventions, and the `.env` contract (injected `MONGODB_URI` for BE; `VITE_API_BASE_URL` for FE) that preview (`phase-15`) and deploy (`phase-37`) honor.
4. **Instantiation contract.** Define exactly how the skeleton is copied into `/workspace` (used by `instantiate_skeleton` in `phase-21` and codegen in `phase-23`): deterministic file copy, `git init` + initial commit ("skeleton"), `pnpm install` — **no LLM involvement** in scaffolding.
5. **CI check.** A job that instantiates the skeleton, installs, builds FE+BE, and runs the placeholder tests.

## Out of scope for this phase

- Feature generation (`phase-23`), test generation (`phase-27`), DB provisioning (`phase-36`) — the skeleton just *reads* an injected URI. No app-specific code.

## Acceptance criteria

- Instantiating the skeleton into a sandbox and running it **boots FE + BE**, the BE connects to a provided `MONGODB_URI`, and the placeholder Vitest/Jest/Playwright tests pass.
- The FE ships with Tailwind already configured and a working API client — **zero** frontend scaffolding needs to be generated by the LLM.
- The skeleton is copied deterministically (no model tokens spent on scaffolding) and committed as the initial git state.

## Tests to write

- `templates/app-skeleton/frontend` — the included Vitest example + a Playwright example (run in CI against a booted preview).
- `templates/app-skeleton/backend` — the included Jest+supertest `/health` test + a Mongoose-connect test against a test URI.
- `backend/tests/agents/test_skeleton_instantiation.py` — copy → `git init` → install → build succeeds (integration behind docker marker).

## Manual verification steps

1. Copy the skeleton into a sandbox; `pnpm install`; start FE+BE via preview → app renders; `/health` OK; BE connects to a test Mongo URI.
2. Run the placeholder test suites → all pass.
3. Confirm Tailwind classes render (example page styled) with no extra setup.

## Rollback / cleanup notes

- Template lives in-repo; instantiated copies live in sandbox volumes (reset via `phase-11`). Reversible.

## Design notes

- **Tailwind in the generated app (user directive).** D2 fixes the stack as React+Vite+TS; adding Tailwind to the *generated-app* FE skeleton is a plan-consistent extension explicitly requested by the user and does not change the stack. Recorded here as the authoritative decision.
- **Always-copy, never-generate** the scaffold: the agent's first Build step is `instantiate_skeleton` (a deterministic copy), then it writes only feature code. This is the core token-saving mechanism.
