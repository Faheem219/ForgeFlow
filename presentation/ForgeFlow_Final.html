Generation Is Mature - Deployability and Human Control Are Not

Agentic generation & issue resolution - a solved-enough problem

LLM4SE survey, SCIS’26 [8]

926 studies systemised across 112 SE tasks and 5 lifecycle phases - LLM use across the lifecycle is no longer in question.

Issue-resolution survey [9]

242 recent studies organised into benchmarks, techniques and empirical work; reinforcement learning is the rising training paradigm.

Agentless, FSE’25 [10]

Structured beats autonomous: a fixed localise → repair → validate pipeline topped open-source agents on SWE-bench Lite (32.0%) at about $0.70 per issue.

RepairAgent, ICSE’25 [11]

An agent that plans its own tool calls fixed 164 Defects4J bugs (39 never fixed before) - at ~270k tokens per bug.

Huang et al., TSE’25 [12]

Larger code models repair better, yet strategies that helped earlier models show no advantage on LLMs - a repair recipe must be re-validated, not assumed.

Design consequence: ForgeFlow takes the Agentless lesson, not the autonomous-agent one - a fixed, deterministic stage pipeline, with a hand-written 53-file app skeleton copied rather than generated.

The deployed artifact still fails - until feedback is added

HULA follow-up [14]

Design2Code, NAACL’25 [15]

484 real webpages: models still lag on visual-element recall and layout - so design stays pluggable and human-refinable.

Iteration Is Not Free - and Generated Tests Decay When Code Changes

Each extra round carries a risk

Security drift, ISTAS’25 [16]

400 samples, 40 rounds of “improve it”: critical vulnerabilities rose 37.6% after five iterations; the authors call for human validation between rounds.

Build code, MSR’26 [17]

Agent-written build code carried 364 maintainability and security smells - yet over 61% of those PRs merged with minimal human review.

Test generation - proven, on a program that holds still

Unit tests, EMSE’26 · ISSTA’25 [18][19]

Across 216,300 generated tests, hallucinated symbols caused up to 86% compile failures [18] - even though fine-tuned LLMs beat prior tools on all three unit-test tasks [19].

E2E & coverage, ICSE’25–’26 [20][21]

Feature-driven E2E tests reach 79% feature coverage on web apps; analysis-guided iteration gives 26% more line and 23% more branch coverage.

TraceLLM, RE’26 [22]

Recovers requirement-to-artifact links after the fact; ForgeFlow builds the link in by construction via criterion_id.

Research Gaps (2/3) - Repair

Repair Fails on Context, Not the Model - and Its Gains Stop Early

Context decides whether a repair is even possible

15–17×

gain from file-level localization over a no-file baseline; best with ~6–10 relevant files, while line-level expansion often adds noise (500 SWE-bench Verified tasks, 61 configurations) [29]

RepoGraph, ICLR’25 [30]

A repository-level code graph - lines as nodes, dependencies as edges - retrieved as k-hop ego-graphs lifts SE agents.

LocAgent, ACL’25 [31]

Dependency graphs plus multi-hop search reach 92.7% file-level localization accuracy.

Tests under evolution [23]

>99% of failing LLM tests still pass on the original program - the model tests code it remembers, so the diff must be highlighted.

Design consequence (phase 63): a deterministic import-graph walk from the failing test (depth ≤ 3, ≤ 24 files) replaces directory-sibling widening - graph-shaped context as in [30][31], with no extra agent turns.

… and the repair loop has an economics

“The first three to four repair iterations account for most achievable gains, while later iterations contribute only marginal improvements.”

Kiecker et al. [32] · Arimbur [33]: across seven models, most gains land in the first two rounds
Context quality [29]

Quality outweighs quantity - hence the per-file (8k) and whole-context (24k-char) caps, with every dropped part counted, never silent.

Design consequence: cap = 5, stall = 2 - plus a new no-op guard: two attempts that write nothing escalate as no_patch with the agent’s own explanation, instead of re-asking the same question.

“

The 2026 evidence says: give the model the right file, and stop early. Phase 63 does both.

Ambiguity Needs a Question, Not a Guess - and a Human in Charge

Models guess when the brief is ambiguous

ClarifyCodeBench [34]

Strong code generators are not strong clarifiers; clarification degrades sharply as ambiguity density rises.

Orchid, 1,304 tasks [35]

Ambiguity degrades every model - most of all the most advanced - and yields functionally divergent code for one request.

… and users must stay in charge

20,574 sessions [36]

91.49% of visible misalignment resolutions still needed explicit user correction.

Practice & roadmap [37][38]

Professionals control rather than delegate; the SASE roadmap calls for agent-initiated human callbacks on ambiguity.

Design consequence: a design provider’s question is parked as a DesignQuestion, the stage goes awaiting_user, and the answer resumes the same provider - no silent failover to a design nobody asked for.
